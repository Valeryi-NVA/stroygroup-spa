# NVA-CRM

NVA-CRM — браузерная CRM с серверной авторизацией и PostgreSQL. Интерфейс не
хранит данные компании в `localStorage`: рабочие записи отправляются в API и
сохраняются в отдельной PostgreSQL-базе каждой компании. Вкладки браузера
содержат только краткоживущий токен входа в `sessionStorage`.

## Возможности

- Регистрация и вход с проверкой пароля на сервере (`scrypt`).
- Новая регистрация создаёт изолированное рабочее пространство компании.
- Администратор компании добавляет пользователей и назначает им роли.
- Вход по bearer-сессии с ограниченным сроком действия.
- PostgreSQL: проекты/объекты, сотрудники, табели, выезды, сдельные работы,
  автопарк, фактические расходы и поступления.
- Проверка прав на сервере и контроль конфликтующих обновлений через версию
  состояния. Изменения пользователей записываются в журнал аудита.
- Стиль Liquid Glass: тёмная чёрно-зелёная тема и переключаемая светлая
  бело-зелёная.

## Локальный запуск

Требуются Node.js 20+ и PostgreSQL. Создайте пустую базу и задайте переменные:

```powershell
$env:DATABASE_URL = "postgres://user:password@localhost:5432/nvacrm"
$env:AUTH_SECRET = "replace-with-a-random-secret-at-least-32-characters"
npm ci
npm run db:init
npm start
```

Откройте `http://localhost:10000`. При регистрации первый пользователь
создаёт администратора своей компании. Демо-аккаунтов и паролей по умолчанию
нет.

## Публикация на Render

В репозитории есть `render.yaml` с Node.js web service и PostgreSQL. В Render
выберите **New → Blueprint**, подключите репозиторий
`Valeryi-NVA/stroygroup-spa`, затем примените blueprint. Он задаёт `AUTH_SECRET`
автоматически, выполняет миграцию таблиц и запускает приложение. URL сервиса
появится в панели Render после успешного деплоя.

GitHub Pages не используется: статический хостинг не может выполнять API и
сохранять серверную базу. При работе на бесплатном плане Render веб-сервис
может засыпать после бездействия, а бесплатная PostgreSQL-база ограничена по
сроку жизни и не предоставляет надёжные резервные копии. Для реальных данных
нужны платный тариф, резервное копирование и отдельный контроль доступа.

## Границы и безопасность

- Регистрация создаёт отдельную компанию; добавить пользователя в компанию
  может её администратор из раздела «Настройки».
- Администраторы имеют полный доступ; менеджеры ведут объекты, выезды,
  расходы и поступления; бухгалтеры — объекты и финансовые записи; начальники
  цеха — сотрудников, табели, выезды и сдельные работы.
- Остальные роли ограничены чтением доступных им экранов и собственных записей.
- Пароли никогда не хранятся в браузере или в открытом виде; используются
  случайная соль и `scrypt`. Сессии хранятся на сервере в виде хеша токена.
- Передайте пользователям уникальные пароли. Текущая версия — рабочая основа,
  но перед эксплуатацией с реальными данными проверьте настройки резервного
  копирования и тариф облачной PostgreSQL.
